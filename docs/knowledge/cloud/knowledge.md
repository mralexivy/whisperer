# Whisperer Cloud — facts learned building it

Paid, end-to-end-encrypted history sync. App Store build only. Plan: `docs/exec-plans/cloud-sync-implementation.md`.

## Architecture in one paragraph
Four Google services and nothing else: Cloud Run (Go control plane), Cloud Storage (ciphertext), Firestore
(control plane docs), Secret Manager. The Mac talks to Cloud Storage directly through V4 signed URLs the server
signs with IAM `signBlob` (no key file); the server never carries user data. Retention deletion runs inside Apple
notifications and sessions — there is no Cloud Scheduler (decided 2026-11-13).

## Facts
- **Cloud Run reserves `/healthz`.** Its front end answers it with a 404 before the container sees it. The
  service is probed at `/v1/health`.
- **No Docker, no Cloud Build.** The image is one layer: the static linux/amd64 binary plus a CA bundle,
  built and pushed to Artifact Registry by a small stdlib Go program over the registry HTTP API. A scratch image
  needs `SSL_CERT_FILE` and `USER 65532`.
- **Firestore over REST works with stdlib only.** Zero times must not be stored (a range query would match
  them); every transaction attempt must restart from the stored document, not the previous attempt's edits;
  create-if-absent maps to `ALREADY_EXISTS`/`FAILED_PRECONDITION`. Verified against real Firestore: 12 concurrent
  transactional updates, none lost.
- **A signed Cloud Storage URL signs its headers.** `x-goog-if-generation-match: 0` and
  `x-goog-content-length-range` are part of the signature, so the grant returns them and the client must send
  them verbatim. Large objects get a signed `POST` with `x-goog-resumable: start`; the session URI that comes
  back needs no signature.
- **The key proof is keyed with the verifier.** The server stores only `SHA-256(authKey)`, so it cannot check an
  HMAC keyed with `authKey`; the proof is `HMAC(verifier, challenge‖deviceId‖suffix)`.
- **Wire formats are pinned by vectors made by the other side.** A signature and key proofs generated by the Go
  server code are verified in the Swift tests; two agents written in parallel had disagreed on both.
- **App Store Connect:** `SUBSCRIPTION_CREATION_NOT_ALLOWED` until the Paid Apps agreement + banking/tax are
  active. The grace period (16 days) and the sandbox notification URL (V2) can be set by API anyway. The
  App Store Server API needs an *In-App Purchase* key, which the API cannot create.
- **Reading uncertainty as expiry is the dangerous bug.** Apple unreachable, unknown transaction, unknown status
  code and an unverifiable JWS must all mean "do not delete".

## Rules
- Never delete a paying user's data. A lapsed user's data survives a read-only window (180/120/90/60 days by
  plan), a 14-day seal and a 7-day soft-delete; every destructive step re-asks Apple first and stops on doubt.
- A replaced (reset) library epoch is held 7 days before any byte is deleted.
- The sync engine never changes the Core Data model or store options; per-row sync state lives in a sidecar.
- `CloudFeature.isLive` is the single release switch; nothing Cloud shows before it is flipped.
